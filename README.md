# Office Simulator

Один русскоязычный мастер устанавливает офисную симуляцию на три указанных хоста. Координатор Linux создаёт учебный трафик SMTP, IMAP, DNS и HTTP. На двух доменных компьютерах Windows работают по 15 задач от имени сотрудников. Они создают, читают и изменяют учебные документы в выделенном каталоге SMB. После закрытия мастера симуляция продолжает работу через systemd и Планировщик задач.

## Запуск

В терминале macOS или Linux нужны Bash, curl и Python 3.11 или новее. На компьютере администратора мастер работает от обычного пользователя.

~~~bash
curl -fsSL https://raw.githubusercontent.com/Sauke5/office-simulator/main/install.sh | bash
~~~

Для SOCKS5 с авторизацией подставьте адрес своего прокси и логин в оба места. curl запросит пароль для загрузки. Мастер отдельно запросит пароль для клиентских библиотек и удалённых подключений. Пароль можно вводить со спецсимволами прямо в приглашении терминала.

~~~bash
curl -fsSL --proxy 'socks5h://proxy.example:1080' --proxy-user 'LOGIN' \
  https://raw.githubusercontent.com/Sauke5/office-simulator/main/install.sh |
  bash -s -- --proxy 'proxy.example:1080' --proxy-user 'LOGIN'
~~~

Пример команды для просмотра плана до подключения к хостам.

~~~bash
curl -fsSL https://raw.githubusercontent.com/Sauke5/office-simulator/main/install.sh | bash -s -- --plan
~~~

## Первый запуск

1. Откройте **«Настроить профиль офиса»**. Мастер читает готовый `office.json`, принимает CSV, список 30 логинов либо выгружает сотрудников из указанной группы или OU в AD. Для выгрузки нужен Windows-хост с модулем ActiveDirectory. При чтении через отдельный контроллер домена укажите его DNS-имя и выберите учётную запись с правом чтения каталога.
2. Задайте два имени Windows-компьютеров, домен, SMB-шару и отдельный каталог офиса, SMTP/IMAP, DNS, HTTP-прокси для веб-трафика и расписание. Мастер распределит сотрудников между компьютерами. В CSV можно закрепить каждого за конкретным клиентом.
3. Выберите **«Установить симулятор»** и хосты. Для Linux введите адрес SSH и логин с правом sudo либо root. Доступны пароль и ssh-agent. При первом соединении сверьте отпечаток ключа с администратором сервера. Для Windows укажите адрес WinRM HTTPS, логин администратора и при необходимости публичный PEM центра сертификации.
4. Мастер проверит SSH, права на Linux и соответствие Windows-хостов домену и профилю. После подтверждения плана он запросит пароли сотрудников поимённо. Если у сотрудника для почты и Windows одна учётная запись, её пароль достаточно ввести один раз.
5. После установки выберите проверку почты или полный проход. Проверка входа открывает 30 ящиков по IMAP. Полный проход также проверяет DNS и HTTP-прокси, отправляет до 30 учебных писем и проверяет их получение. Затем подтвердите запуск. Пункт **«Показать состояние и последние события»** показывает состояние systemd, задачи каждого сотрудника и последние доступные события Windows.

Профиль и параметры подключений сохраняются в `~/.config/office-simulator`. Пароли администратора и SOCKS5 запрашиваются в терминале. При первом сетевом действии мастер загружает SSH- и WinRM-библиотеки с PyPI и проверяет зафиксированные SHA-256. Последующие запуски используют личный кэш. Для второго офиса задайте отдельный каталог через `--state-dir`.

## Что подготовить на хостах

| Компонент | Требования и результат |
|---|---|
| Linux | Работающий systemd и SSH. Координатору нужны Python 3.11+, `dig` и `runuser`. При нехватке зависимостей мастер использует APT или DNF. Подходит Debian 12 с обычными репозиториями. По умолчанию создаётся системный пользователь `office-sim`. |
| Windows | Два компьютера в указанном AD-домене, Windows PowerShell 5.1 и WinRM HTTPS с NTLM (обычно порт 5986). Нужны доверенный сертификат с именем хоста и локальные административные права для установки. Политика PowerShell должна разрешать локальные скрипты комплекта. Сотрудникам нужны право пакетного входа и доступ к рабочему каталогу SMB. |
| Службы офиса | 30 действующих доменных записей и почтовых ящиков, существующая SMB-шара, доступные DNS, SMTP с TLS, IMAPS и HTTP-прокси. Мастер устанавливает клиентов и координатор в этой среде. |
| SOCKS5 | Через него идут загрузка клиентских библиотек и соединения SSH/WinRM. Для установки недостающих системных пакетов мастер отдельно спрашивает, передать ли настройки SOCKS5 менеджеру пакетов Linux. В этом случае адрес прокси должен быть доступен и с Linux-сервера. HTTP-прокси в профиле офиса служит для имитации веб-трафика сотрудников. |

На Windows текущие WinRM listeners можно посмотреть командой `winrm enumerate winrm/config/listener`. [Настройка WinRM HTTPS в документации Microsoft](https://learn.microsoft.com/en-us/troubleshoot/windows-client/system-management-components/configure-winrm-for-https)

## Повторный запуск и диагностика

Сохранённый профиль открывается тем же установщиком. Для изменения программы, профиля или паролей выберите **«Обновить»**. При частичном сбое мастер показывает хосты, на которых операция завершилась. Для повторного применения можно выбрать один хост. После успешной проверки почты или полного прохода ранее работавшая Linux-служба возобновляется. При ошибке проверки мастер сообщает её состояние.

Пункт **«Снять автозапуск»** останавливает симуляцию, выключает автозапуск Linux-службы и снимает зарегистрированные задачи Windows выбранного офиса. Конфиги, журналы и созданные документы сохраняются. Для просмотра сетевых интерфейсов, DNS и аренды DHCP на Windows используйте **«Показать сетевые настройки Windows»**.

| На хосте | Где посмотреть |
|---|---|
| Служба Linux | `systemctl status office-simulator.service`. Текущая версия расположена в `/opt/office-simulator/current`. |
| Журнал Linux | `/var/lib/office-simulator/logs/linux.jsonl` содержит события фоновой службы и ручных проверок. Учётные данные почты хранятся на сервере в `/opt/office-simulator/current/private/secrets.json`, режим 600. |
| Windows | Конфигурации и журналы находятся в `%ProgramData%\OfficeSimulator`. Планировщик сохраняет учётные данные задач и запускает их при загрузке компьютера. |
| Мониторинг | `--export` выгружает примеры Alloy, панели Grafana и метрик Prometheus. Инструкция находится в `monitoring/README.md` внутри выгруженного каталога. |

Чтобы сохранить скрипт и обращаться к нужному действию напрямую, выполните следующие команды.

~~~bash
curl -fsSL https://raw.githubusercontent.com/Sauke5/office-simulator/main/install.sh -o install.sh
bash install.sh --self-test
bash install.sh --export ./office-examples
bash install.sh --plan --manifest ./office-examples/office.example.json
bash install.sh --action configure --roster ./users.csv
bash install.sh --action preflight --target all
bash install.sh --action status --target win1
bash install.sh --help
~~~

Для журналов Office Sparring включён автономный HTML-отчёт. Для подготовки отчёта по завершённому эпизоду выполните `bash install.sh --report ./episode.jsonl --output ./episode.html`.

Чтобы прочитать код мастера и обеих удалённых ролей, выполните `bash install.sh --unpack ./office-source`. В новом каталоге будут исходники Python и PowerShell, список закреплённых зависимостей и файл `bundle.json` с контрольными суммами комплекта.
